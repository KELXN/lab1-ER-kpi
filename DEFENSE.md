# DEFENSE — Захист ER-моделі даних (Gadget Zone)

## 1. Намір і критерії
Спроєктувати нормалізовану до 3NF модель даних для інтернет-магазину «Gadget Zone» з єдиною типізацією ідентифікаторів та повною відсутністю дублювання даних.

## 2. Топ-3 розбіжності та виправлення
1. **Зберігання ціни товару у замовленні:** Початково ціна планувалася тільки в таблиці `Product`. Виправлено у `spec.md` додаванням атрибута `unit_price` до `OrderItem`, щоб зафіксувати ціну на момент купівлі (коміт `fix: add unit_price to order items`).
2. **Типізація зовнішніх ключів:** Виявлено різнобій між `uuid` та `int`. Уніфіковано всі ідентифікатори до типу `string` у `spec.md` (коміт `refactor: unify id types to string`).
3. **Статус замовлення:** Замість булевого прапорця введено текстове поле `status` в сутність `Order` для підтримки розширеного життєвого циклу замовлення (коміт `feat: add order status field`).

## 3. Ключове рішення (ADR)
Обрано декомпозицію зв'язку M:N між `Order` та `Product` через асоціативну сутність `OrderItem` з урахуванням кількості та фіксованої ціни замість прямого зв'язку чи масиву ідентифікаторів (деталі у `docs/adr/001-order-item-association.md`).

## 4. Перевірка
Модель перевірена на відповідність 3-й нормальній формі (3NF). Усі назви та кардинальності зв'язків у `spec.md` повністю збігаються з ER-діаграмою.
